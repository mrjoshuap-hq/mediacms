    Release notes: v10.0.0 (stable)¶

    Draft for review

    These notes are a draft for the first fork stable release. Joshua Preston (@mrjoshuap) sets the tag date when he tags main. Until then, the tag is written as v10.0.0.YYYYMMDD. A second cut on the same date uses v10.0.0.YYYYMMDD.N.

    This release promotes the fork beta line mediacms-next to main. It is the first stamped stable release of the mrjoshuap fork. Compared with upstream MediaCMS 9.4.0 (fork main at e25fb95), it adds an admin portal rework, aligned permissions, password-protected media, sharded media paths, structured logging, MkDocs documentation, and a GHCR release pipeline.

    • Version base: 10.0.0 from version/FORK_VERSION (869ec5b). package.json stays at 9.4.0 on purpose. Fork releases do not use semantic-release (5455a7e).
    • Full diff: main...mediacms-next.
    • Beta builds that came before this release: v10.0.0.20261114, v10.0.0.20261115, and v10.0.0.20261115.1. These are pre-releases on mediacms-next. They are not stable releases.

    Before you upgrade¶

    Back up first

    Back up PostgreSQL and media_files before you upgrade. This release has 10 new Django migrations. One of them removes a column. See Models and migrations.

    1. Read Breaking changes and Permission access changes.
    2. Back up the database and media_files.
    3. Set MEDIACMS_IMAGE in your Compose environment. See Container images.
    4. Pull the image and let the migrations container run, or run python manage.py migrate once.
    5. Rebuild the frontend if you do not use the image static files. See Frontend.
    6. Restart web, celery_worker, and celery_beat.
    7. Follow Upgrade tips for the full checklist.

    Container images¶

    The stable pipeline in .github/workflows/release.yml runs when a v10.0.0.YYYYMMDD[.N] tag is pushed on a commit that is on main (5455a7e, 869ec5b). It runs pre-commit, the Python tests, and the frontend build, then publishes these tags to GHCR:

    Image Tags from a stable tag
    ghcr.io/mrjoshuap/mediacms :stable, :10.0.0.YYYYMMDD[.N], :sha-<7>, :upgrade-audit
    ghcr.io/mrjoshuap/mediacms-full (Whisper) :stable, :10.0.0.YYYYMMDD[.N], :sha-<7> 
    docker pull ghcr.io/mrjoshuap/mediacms:stable
docker pull ghcr.io/mrjoshuap/mediacms:10.0.0.YYYYMMDD
docker pull ghcr.io/mrjoshuap/mediacms-full:stable

    The GitHub Release body comes from the generated INSTALL-stable.md asset plus GitHub generated notes. The workflow does not read this page. The release also attaches source archives, a docs archive, the OpenAPI file, and SHA256SUMS.

    Breaking changes¶

    • Compose default image. docker-compose.yaml and the other Compose files now use image: ${MEDIACMS_IMAGE:-mediacms:local} instead of mediacms/mediacms:latest (f349fa8). Set MEDIACMS_IMAGE (for example ghcr.io/mrjoshuap/mediacms:stable), or run make docker-build first. Without one of these, docker compose up looks for a local mediacms:local image.
    • Permissions and roles. Server ACLs and frontend can.* flags now follow the roles and permissions guides (cc139aa, 5fe7cee). Editors lose Manage users. Pending users can no longer comment, like, report, or use manage APIs. Co-owners and RBAC category managers can delete media. See Permission access changes.
    • User.media_count removed. Migration users.0003_remove_user_media_count drops the column. Counts now come from listable media at query time (d69a163). Custom code or reports that read media_count must change.
    • Media password storage. files.0023_alter_media_password stores a hashed Media.password (6971422).
    • New media file paths. New uploads use sharded <kind>/<aa>/<bb>/<uid>/… paths. Existing files stay on legacy paths until a manager runs Migrate paths (f349fa8). Custom nginx configs need the thumbnails, categories, and subtitles location blocks from deploy/docker/nginx_http_only.conf (f349fa8).
    • Search. Media search treats CJK tokens with icontains, so result sets can change for CJK queries (0b8f983).

    Rollback

    users.0003 removes a column. If you roll back, the column comes back empty. Restore from the backup instead of migrating backwards.

    Extra steps by change (from the Upgrade impact table on What's new, 5ea8fac):

    Change Migrations Frontend build Language rebuild Restart
    Permission ACL alignment No Yes No web (and Celery)
    Password-protected media Yes Yes If new UI strings ship web, celery_worker
    Site upgrade tooling Yes No No web
    Admin portal dashboards and health Yes No Optional web
    Logging and trusted proxies No No No web, celery_worker, celery_beat
    HLS and encoding tasks No No No celery_worker, celery_beat
    Sharded paths, path migrate, filesystem library Yes Yes Yes web, celery_worker, celery_beat

    For a large portal, run python manage.py upgrade_site inventory and a scratch migrate on a copy of the database first (07a0c1c). See Site upgrade.

    Features¶

    Admin portal¶

    • Workflow sidebar with Moderation, Library, Processing, People, Integrations, and Site groups (58f59ce, merged in 54f39b4).
    • Dashboard statistics and MediaAction indexing (ddc4940, e6a4ffe).
    • Site Health checks and installation details (7b28e27).
    • Database backup download and restore upload for superusers, with optional engagement rows (bcb3bf6, 07a0c1c).
    • Redacted support bundle (ba548c2).
    • Optional changelist columns and icons (bc84b1a, 363e81a).
    • Grouped action choices and object actions (320c34b, a12a771).
    • Media and metadata integrity checks in Site Health and Library (f4b4e97, 934d73c).
    • Admin language chooser (bd1a9b7).
    • upgrade_site command and the UpgradeDecision model (07a0c1c).
    • populate_fake_media command, gated by ALLOW_POPULATE_FAKE_MEDIA (9b01ea8, 385d4e9).

    Media and playback¶

    • Password-protected media with a session unlock API, POST /api/v1/media/{token}/unlock (6971422).
    • Incremental HLS packaging with an optional full rebuild (0e47900).
    • Optional title, description, and other metadata on upload (9c30638).
    • Next and previous navigation keeps fullscreen and autoplay (29131b3).
    • Lazy playlist membership for the Save popup, GET /api/v1/media/{token}/playlists (88a5ecb).
    • Playlist annotations, delete confirmation, and visibility-aligned counts (2acb2f4).
    • Alphabetical tag and category lists (8242b33).
    • CJK-aware media search (0b8f983).
    • cleanup_encoding_chunks beat task and ENCODING_CHUNKS_RETENTION_HOURS (eb74784).
    • Sharded media paths, gated Migrate paths, and a Filesystem library source under FILESYSTEM_IMPORT_ROOT (f349fa8).

    Operations and settings¶

    • Structured logging with LOGLEVEL and optional SQL debug logging (41e39ba, 7c21bdc, merged in 2bbc0cd).
    • Failed-login warnings with the client IP (f045cf1).
    • TRUSTED_PROXIES reverse-proxy support. It is off when the list is empty (a0d7b2d, 12d088e).
    • EMAIL_TIMEOUT and visible SMTP errors on contact forms (9c7d4e4).
    • CAN_SEE_MEMBERS_PAGE = "anonymous" option (138eacc).

    Documentation and delivery¶

    • MkDocs documentation at /documentation/ (5d0eb25) and admin portal guides (f40b0d4).
    • Versioned docs with mike through the GitHub Pages Actions deploy (edeb037).
    • Curated fork notes in docs/_shared/fork-whats-new.md (4b09fa4) and the Upgrade impact table (5ea8fac).
    • Releases section: compare, features, fixes, frontend, migrations, upgrade tips (f349fa8).
    • GHCR date-stamped beta and stable pipeline (5455a7e, 869ec5b).
    • Frontend lint in pre-commit (24dc20c) and an @unimplemented test helper (7792aec).
    • Agent guidance: AGENTS.md change impact policy and skills (f349fa8), the maintainer skill (#82), and the plan archive under .agent/plan-history/ (7eb9447). The plan catalog indexes every plan note and takes each date from the note or from git, not from file modification time (#116).

    Bug fixes¶

    • Chapters overlay opens on desktop click (741bf3f).
    • Chapter seek and save stay stable after a split while paused (af6a5b5).
    • Search vector and tag and category counts update when M2M links change (5af932f).
    • Media review handles string inputs such as "false" (459710e).
    • Sidebar Home link is active on / (a2c52ee).
    • Template context defaults stop AttributeError log floods (f86371b, 68cbf38).
    • SignupForm circular import (8f92a2d).
    • "Chunk already combined" encoding error (edbc826).
    • CI test failures after the enhanced-logging merge (ebbeacb).

    Known issues¶

    • Beta and stable tags share one name pattern, v10.0.0.YYYYMMDD[.N]. Every push to mediacms-next creates a beta tag for the current UTC date (5455a7e). The stable tag must use a date or .N suffix that no beta tag uses yet.
    • amd64 FFmpeg and Bento4 in Docker builds on arm64 hosts. See Fixes and known issues.
