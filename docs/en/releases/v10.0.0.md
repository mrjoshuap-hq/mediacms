# Release notes: v10.0.0 (stable)

!!! warning "Draft for review"
    These notes are a draft for the first fork stable release. Joshua Preston (@mrjoshuap) sets the tag date when he tags `main`. Until then, the tag is written as `v10.0.0.YYYYMMDD`. A second cut on the same date uses `v10.0.0.YYYYMMDD.N`.

This release promotes the fork beta line `mediacms-next` to `main`. It is the first stamped stable release of the mrjoshuap fork. Compared with upstream MediaCMS 9.4.0 (fork `main` at [`e25fb95`](https://github.com/mrjoshuap/mediacms/commit/e25fb95)), it adds an admin portal rework, aligned permissions, password-protected media, sharded media paths, structured logging, MkDocs documentation, and a GHCR release pipeline.

- Version base: `10.0.0` from `version/FORK_VERSION` ([`869ec5b`](https://github.com/mrjoshuap/mediacms/commit/869ec5b)). `package.json` stays at `9.4.0` on purpose. Fork releases do not use semantic-release ([`5455a7e`](https://github.com/mrjoshuap/mediacms/commit/5455a7e)).
- Full diff: [main...mediacms-next](https://github.com/mrjoshuap/mediacms/compare/main...mediacms-next).
- Beta builds that came before this release: [`v10.0.0.20261114`](https://github.com/mrjoshuap/mediacms/releases/tag/v10.0.0.20261114), [`v10.0.0.20261115`](https://github.com/mrjoshuap/mediacms/releases/tag/v10.0.0.20261115), and [`v10.0.0.20261115.1`](https://github.com/mrjoshuap/mediacms/releases/tag/v10.0.0.20261115.1). These are pre-releases on `mediacms-next`. They are not stable releases.

## Before you upgrade

!!! danger "Back up first"
    Back up PostgreSQL and `media_files` before you upgrade. This release has 10 new Django migrations. One of them removes a column. See [Models and migrations](migrations.md).

1. Read [Breaking changes](#breaking-changes) and [Permission access changes](../guides/admin/permissions-changes.md).
2. Back up the database and `media_files`.
3. Set `MEDIACMS_IMAGE` in your Compose environment. See [Container images](#container-images).
4. Pull the image and let the `migrations` container run, or run `python manage.py migrate` once.
5. Rebuild the frontend if you do not use the image static files. See [Frontend](frontend.md).
6. Restart `web`, `celery_worker`, and `celery_beat`.
7. Follow [Upgrade tips](upgrade-tips.md) for the full checklist.

## Container images

The stable pipeline in `.github/workflows/release.yml` runs when a `v10.0.0.YYYYMMDD[.N]` tag is pushed on a commit that is on `main` ([`5455a7e`](https://github.com/mrjoshuap/mediacms/commit/5455a7e), [`869ec5b`](https://github.com/mrjoshuap/mediacms/commit/869ec5b)). It runs pre-commit, the Python tests, and the frontend build, then publishes these tags to GHCR:

| Image | Tags from a stable tag |
|-------|------------------------|
| `ghcr.io/mrjoshuap/mediacms` | `:stable`, `:10.0.0.YYYYMMDD[.N]`, `:sha-<7>`, `:upgrade-audit` |
| `ghcr.io/mrjoshuap/mediacms-full` (Whisper) | `:stable`, `:10.0.0.YYYYMMDD[.N]`, `:sha-<7>` |

```bash
docker pull ghcr.io/mrjoshuap/mediacms:stable
docker pull ghcr.io/mrjoshuap/mediacms:10.0.0.YYYYMMDD
docker pull ghcr.io/mrjoshuap/mediacms-full:stable
```

The GitHub Release body comes from the generated `INSTALL-stable.md` asset plus GitHub generated notes. The workflow does not read this page. The release also attaches source archives, a docs archive, the OpenAPI file, and `SHA256SUMS`.

## Breaking changes

- **Compose default image.** `docker-compose.yaml` and the other Compose files now use `image: ${MEDIACMS_IMAGE:-mediacms:local}` instead of `mediacms/mediacms:latest` ([`f349fa8`](https://github.com/mrjoshuap/mediacms/commit/f349fa8)). Set `MEDIACMS_IMAGE` (for example `ghcr.io/mrjoshuap/mediacms:stable`), or run `make docker-build` first. Without one of these, `docker compose up` looks for a local `mediacms:local` image.
- **Permissions and roles.** Server ACLs and frontend `can.*` flags now follow the roles and permissions guides ([`cc139aa`](https://github.com/mrjoshuap/mediacms/commit/cc139aa), [`5fe7cee`](https://github.com/mrjoshuap/mediacms/commit/5fe7cee)). Editors lose Manage users. Pending users can no longer comment, like, report, or use manage APIs. Co-owners and RBAC category managers can delete media. See [Permission access changes](../guides/admin/permissions-changes.md).
- **`User.media_count` removed.** Migration `users.0003_remove_user_media_count` drops the column. Counts now come from listable media at query time ([`d69a163`](https://github.com/mrjoshuap/mediacms/commit/d69a163)). Custom code or reports that read `media_count` must change.
- **Media password storage.** `files.0023_alter_media_password` stores a hashed `Media.password` ([`6971422`](https://github.com/mrjoshuap/mediacms/commit/6971422)).
- **New media file paths.** New uploads use sharded `<kind>/<aa>/<bb>/<uid>/…` paths. Existing files stay on legacy paths until a manager runs **Migrate paths** ([`f349fa8`](https://github.com/mrjoshuap/mediacms/commit/f349fa8)). Custom nginx configs need the `thumbnails`, `categories`, and `subtitles` location blocks from `deploy/docker/nginx_http_only.conf` ([`f349fa8`](https://github.com/mrjoshuap/mediacms/commit/f349fa8)).
- **Search.** Media search treats CJK tokens with `icontains`, so result sets can change for CJK queries ([`0b8f983`](https://github.com/mrjoshuap/mediacms/commit/0b8f983)).

## Known issues

- Beta and stable tags share one name pattern, `v10.0.0.YYYYMMDD[.N]`. Every push to `mediacms-next` creates a beta tag for the current UTC date ([`5455a7e`](https://github.com/mrjoshuap/mediacms/commit/5455a7e)). The stable tag must use a date or `.N` suffix that no beta tag uses yet.
- amd64 FFmpeg and Bento4 in Docker builds on arm64 hosts. See [Fixes and known issues](fixes.md).
